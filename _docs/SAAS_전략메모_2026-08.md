# 광고관리 시스템 SaaS화 — 전략 메모 (2026-08-07)

작성 계기: 종민 — 삼성PL·아노쉬 대시보드 개발 중, 목표는 SaaS화. 이 광고관리 구글시트도 발전시킬 수 있는가.

---

## 1. 핵심 판단

**"구글 시트를 더 강력한 대시보드로 발전"이 아니라, 시트에서 검증된 도메인 로직을 백엔드로 들어올리는 재플랫폼이 맞다.** 시트 자체를 SaaS로 키우는 경로는 아래 4대 병목에서 막힌다. "API만 극복하면"은 과소평가 — API/인증은 병목 중 가장 큰 하나일 뿐.

## 2. 진짜 자산 vs 배관

- **진짜 IP(그대로 이식됨)**: 커넥터(메타/네이버/구글/당근/GA4 수집), UTM→GA4 attribution·유입 라우팅 모델, 지표 정의(CPL·카톡전환률·개통·유입별 소스분기·속성별 이벤트명 매핑). = 몇 달치 도메인 로직.
- **배관(기계적 재작성)**: Apps Script 트리거 → 서버 잡러너, 시트 → DB. 어렵지 않음.
- 결론: 어려운 건 이미 만들어졌다. 도메인 모델이 자산, 플랫폼은 갈아끼우는 것.

## 3. 4대 병목 (SaaS 진짜 장벽)

1. **Apps Script 한도** — 6분 실행·트리거·URLfetch 쿼터. 이미 반복적으로 6분 초과. 5~10 브랜드 야간 풀싱크면 벽, 50~100 테넌트는 불가.
2. **시트=DB 한계** — 셀 1000만·동시성·속도. 멀티테넌트 데이터스토어 부적합 → Postgres/BigQuery 필요.
3. **복제본 유지보수** — 브랜드=시트+스크립트 통째 복제(clasp 멀티푸시). N개면 취약 → 단일 코드·단일 DB·테넌트=행.
4. **멀티테넌트 인증/시크릿 = 진짜 "API 문제"** — 고객 셀프 OAuth(Meta/GA4/네이버), 토큰 자동 갱신, 앱 심사(Meta App Review ads_read / Google Ads dev token standard / 네이버 승인), 앱당 레이트리밋. 엔지니어링보다 플랫폼 관료제(수개월). **단, 넘으면 경쟁사도 막히는 해자.**

## 4. 현실적 3단계 경로

- **1단계**: 현 시트 시스템 = 내부 운영툴 + PoC 유지. 도메인 검증 완료 자체가 자산.
- **2단계**: 커넥터를 시트에서 분리 → 작은 서버(잡러너 + DB). 초기엔 자체 토큰 관리(1~3 브랜드). 시트·HTML 대시보드는 그 DB의 뷰로. ← 병목 1·2 해소.
- **3단계**: 셀프 OAuth 온보딩 + 웹 대시보드(아노쉬/삼성PL HTML 자산 재활용) = 멀티테넌트 SaaS. Meta/Google 앱 심사가 관문.

## 5. 실현 가능한 업그레이드 목록 (백엔드 전환 시)

### Tier 1 — 백엔드+DB만 있으면 바로 (현 시트로는 불가)
- **무제한 히스토리**: 지금 GA4 최근 30일·시트 셀 한도 → DB 누적 → YoY·계절성·코호트·기간 자유비교.
- **시간별/온디맨드 갱신**: 지금 야간 1회 + 6분 한도 → 잡러너로 시간별·버튼 클릭 시 즉시 갱신.
- **광고소재(크리에이티브) 단위 성과**: 지금 광고그룹까지 → 소재별 CTR/CPL/피로도(빈도)·썸네일별 비교.
- **크로스채널 통합 어트리뷰션**: 지금 채널별 시트 분리 → 메타/네이버/구글/당근/GA4 한 모델에서 채널기여·중복제거.
- **이상탐지 고도화**: 지금 alerts.js 고정임계 → 통계적(추세·분산 기반) CPL 급등·지출0문의0·소진 이상 자동 감지.
- **자연어 Q&A/브리핑**: 지금 아침브리핑(고정 템플릿) → "지난주 왜 CPL 올랐어?" 데이터 위 LLM 응답.

### Tier 2 — 중간 노력
- **attribution 유실 복구**: 이번에 확인된 cross-network/not set 유실(랜딩 78세션 중 34만 매칭) → 서버사이드 태깅 / fbclid·gclid 클릭ID 매칭 / GA4 Measurement Protocol로 근본 해결.
- **이벤트 품질 정규화**: 이번에 본 kakao_click 세션당 중복발화(29회/3세션) → 서버에서 세션당 dedupe·유효클릭 정의 표준화.
- **예산 최적화 추천**: 광고그룹별 한계CPL 기반 예산 재배분 제안(집행 자동화는 별개).
- **예측**: 지출→문의→개통 퍼널 예측, 월말 CPL·개통 착지 예상.
- **리포트 자동생성·발송**: 고객별 주간 PDF/링크, 화이트라벨(로고·도메인).
- **알림 채널 확장**: 텔레그램 → 슬랙/카톡/이메일/웹푸시.

### Tier 3 — SaaS 본격 (어려움 = 관료제·플랫폼)
- **셀프서브 온보딩**: 고객이 OAuth로 Meta/GA4/네이버 자가 연결(수동 토큰 붙여넣기 제거).
- **역할/권한**: 대행사 ↔ 광고주 뷰·권한 분리, 멀티유저.
- **구독/과금**: 요금제·결제.
- **앱 심사 통과**: Meta App Review·Google Ads standard access·네이버 승인 = 3단계 관문이자 해자.

### 실현성 메모
- Tier 1은 2단계(백엔드+DB) 완료 시 대부분 부수효과로 딸려옴 = 투자 대비 효과 큼.
- Tier 3의 앱 심사는 코드가 아니라 시간·정책 이슈 → 일정 리스크는 여기 집중.
- 광고 **집행 자동화**(예산 자동조정·소재 자동생성)는 성과 API(read)와 별개인 write 권한·리스크라 별도 단계로 분리 권장.

## 6. 이번 프로젝트가 남긴 근거 (재플랫폼 시 그대로 반영)

- 유입맵/속성-라우팅 모델(`_유입맵` → 라벨별 SUMIFS 중첩 IF): DB에선 tenant×property 매핑 테이블로 자연 이식.
- 속성별 이벤트명 상이(kakao_chat_click/kakao_click/chat_click): 백엔드 이벤트 정규화 레이어로.
- utm_campaign 미집계·이벤트 중복: Tier 2 attribution/품질 항목의 실제 근거.
- 6분·30일 한도: 병목 1·Tier1 무제한 히스토리의 실제 근거.
