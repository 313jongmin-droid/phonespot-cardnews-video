# 생성 플랫폼 1원화 가이드 (create 축) — 2026-08-07

배경: 배너 생성기·카드뉴스·AI뉴스·쇼츠·프로모가 여기저기 흩어져 있음. 1원화 검토.
핵심 원칙: **"한 프로그램에 몰아넣기"가 아니라 "공통 코어를 뽑고 렌더러는 꽂아 쓰기".**

---

## 0. 현재 지형 (파편 위치)

| 생성기 | 위치 | 런타임 |
|---|---|---|
| 광고 배너 생성기 (BP 브랜드프로필/캐러셀/실사) | 구글시트 Apps Script (`ads/`) | Apps Script |
| 카드뉴스 | `phonespot_cardnews/cardnews` | 로컬 Python/Node |

→ 런타임·포맷 제각각. 각자 잘 돌지만 브랜드 정의·에셋·주제 로직이 중복.

---

## 1. 1원화되는 것 (공통 코어) — 가치 큰 순서

### ① 브랜드 정의 (Single Source of Truth) — 제일 싸고 효과 큼
- 브랜드 보이스·컬러·로고·제품 팩트·오퍼·용어("할부원금")·금지룰(promo_ai 부메랑 금지)를 **한 곳**에.
- 지금은 배너(BP), 카드뉴스, Anosh가 각자 보유 → 오퍼 하나 바꾸면 전부 수동 반영.
- 통합 후: 브랜드코어 1개 수정 → 배너·카드뉴스·뉴스·영상 전부 자동 반영.
- **브랜드코어 스키마 초안**(뽑아낼 필드):
  - identity: brandName, logo, palette[], font, tone(격식/캐주얼), 금지표현[]
  - product: 카테고리[], 핵심팩트[](요금·기종·혜택), 오퍼[](기간·조건), CTA[]
  - copy_rules: 슬로건 규칙, 용어사전(정규화), 강조/차별 포인트
  - visual_rules: AD_STYLE, 실사/일러스트 기준, 씬 포맷
  - channel: UTM 규칙, 랜딩 URL, GA4 속성 매핑(← 데이터축과 연결점)

### ② 에셋 라이브러리
- 생성·승인된 이미지·제품컷·과거 소재를 한 저장소에서 모든 생성기가 재사용.
- 지금 CLIP/임베딩 캐시(`image_embed_cache.json`)가 프로젝트별로 쪼개짐 → 통합.

### ③ 주제·뉴스 선정 브레인
- "뭘 만들지"(토픽 엔진·뉴스 선정·성과 피드백)를 하나의 두뇌로.
- 그 출력(brief)이 배너/카드뉴스/쇼츠로 각각 렌더.

### ④ 작업 큐 + 승인·발행
- brief → 생성 → 검수 → 발행을 **포맷 무관 한 파이프라인**으로.

---

## 2. 안 합치는 것 (플러그인으로 유지 = 정답)

- **렌더러**: 배너(이미지 생성) / 카드뉴스(멀티슬라이드) / 쇼츠(Remotion 영상) / 뉴스(텍스트).
- 기술이 근본적으로 다름 → 공통 코어에 물리는 **output adapter**로 두고 코드 통합은 후순위/선택.

---

## 3. 궁극 목표 = 폐루프 (measure → create → act)

- **measure**: 메타/GA4 데이터 — 어떤 소재·주제가 CPL 낮았나 (데이터축).
- **create**: 그 신호로 brief 자동생성 → 생성기 → 신규 소재 (create축, 이 가이드).
- **act**: 메타 API로 광고 런칭·예산 (act축).
- → 다시 measure. **성과가 "다음에 뭘 만들지"를 자동으로 정해 생성기에 먹이는 루프 = 진짜 값이자 해자.**
- 세 축이 **하나의 브랜드코어(①)** 위에서 돈다 = 마케팅 SaaS의 심장.

---

## 4. 실현 순서 (파편 안 깨고 점진)

1. **브랜드 정의 1원화** — 브랜드코어 스키마 확정 + 각 생성기가 그걸 읽게(어댑터). ← 지금 당장 착수 가능, 리스크 낮음.
2. **에셋 라이브러리 공유** — 단일 저장소 + 임베딩 캐시 통합.
3. **주제 브레인 통합** — 토픽/뉴스 선정 + 성과 피드백 한 곳.
4. **큐·검수·발행 통합**.
5. **성과 피드백 루프** — measure축과 연결.
- 렌더러 코드 통합은 맨 마지막이거나 생략.
